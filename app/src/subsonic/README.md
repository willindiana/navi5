# Subsonic client

Blocking, injected GET transport; no UI or account persistence. Example:

```cpp
#include "subsonic/subsonic.h"
#include "subsonic/http_jf.h"

subsonic::Client client(server, username, password, subsonic::http_get_jf);
subsonic::ServerInfo info;
std::string error;
if (!client.ping(&info, &error)) {
    // Show error; never print request URLs.
}
```

`http_get_jf` uses existing FFmpeg avio HTTP on console and existing curl HTTP
in host tests. Inject another `HttpGet` for fixtures. Caller must supply non-null
output/error pointers and a thread-safe transport for concurrent use. Configure
auth before sharing the client. Results replace output on success.

Auth uses fresh salt and FFmpeg `av_md5_sum(password + salt)` per URL;
`set_api_key` switches to `apiKey` alone (no `u`, `t`, `s`). Empty key restores
token auth. A persisted token+salt pair is password-equivalent and replayable,
not a genuinely safer stored secret. Use HTTPS; never log or persist credential
URLs. `redact_url` handles credential query parameters generated by this client.
Disable verbose HTTP/FFmpeg URL logging in application integration as well.
Transport diagnostics are intentionally not forwarded because they may contain
URLs. API errors retain server message and code.

## Host checks

Requires clang, pkg-config, libavutil, libcurl. No private environment file read.

```sh
./app/tests/host/subsonic.sh
NAVI5_SANITIZE=1 ./app/tests/host/subsonic.sh
NAVI5_LIVE=1 ./app/tests/host/subsonic.sh
```

Offline checks always run. Live opt-in only contacts public Navidrome demo;
write endpoints only use fixtures. Stream/cover-art builders perform no request.

## Integration ceiling

Only new files were permitted for NAVI5-10. Existing `app/Makefile` explicitly
lists source directories, so main application build does not yet compile this
directory. Add `$(wildcard src/subsonic/*.cpp)` to `APP_CXX` during integration;
libavutil and cJSON are already linked. No extra library needed. Actual app
objects currently use C++17 (`app/Makefile`); only CRT/runtime build commands
explicitly use C++20, `-fno-exceptions`, `-fno-rtti`. Host checks use C++20 and
both no-exception/no-RTTI flags; client itself requires only C++17.

PS5 SDK link, entropy behavior, HTTPS and playback remain console-unverified.
Salt uses FFmpeg `av_get_random_seed`, not a new crypto implementation. In
FFmpeg 7.0 it tries platform randomness (`arc4random_buf`, `/dev/urandom`, or
configured crypto backend) and otherwise falls back to timing-derived seed
material. Actual PS5 build configuration and sandbox entropy access have not
been verified; cryptographic-strength randomness is not guaranteed. The local
atomic counter avoids repeated salts within one process, not across restarts.
Upstream timing fallback also uses shared mutable state: do not assume its
thread safety without verifying the console's entropy path.
Source: https://github.com/FFmpeg/FFmpeg/blob/n7.0/libavutil/random_seed.c

`get_album_list(..., from_year, to_year)` supports `byYear` with both bounds
required, each in the client's accepted range 0..9999. Reverse bounds are valid
and request descending order. Existing calls for other list types are unchanged.
Spec: https://opensubsonic.netlify.app/docs/endpoints/getalbumlist2/

`Lyrics::offset` preserves signed milliseconds (default 0). Positive means
lyrics appear earlier: effective time is `(long long)line.start - lyrics.offset`.
Raw timestamps are not shifted or clamped to zero, including when effective
time is negative; presentation policy belongs to the consumer.
Spec: https://opensubsonic.netlify.app/docs/responses/structuredlyrics/

`NAVI5_CXX_STD=c++17 ./app/tests/host/subsonic.sh` checks C++17 compatibility.
Sanitizer mode instruments both the C++ client and cJSON C compilation.

## NAVI5-17: API key authentication (verified 2026-11-05)

Public demo reports Navidrome `0.64.2 (10114574)`, `openSubsonic=true`.
`getOpenSubsonicExtensions` lists transcodeOffset, formPost, songLyrics,
indexBasedQueue, transcoding, playbackReport and topSongsByArtistId; **no
apiKeyAuthentication**. Latest stable release is still v0.64.2 (2026-09-24).

API key authentication was merged upstream on 2026-09-28 in PR #6219, after
that release. Thus development code supports it, demo/current stable does not.
Do not infer support from `openSubsonic=true`; check advertised extension.
No real API key was created or tested live.

Sources:
- https://www.navidrome.org/docs/developers/subsonic-api/ (links extension tracker)
- https://github.com/navidrome/navidrome/issues/2695 (development, not stable list)
- https://github.com/navidrome/navidrome/pull/6219 (merge date and API semantics)
- https://github.com/navidrome/navidrome/releases/tag/v0.64.2
